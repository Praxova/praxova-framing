# Praxova Framing v0.5 Design — Door and Window Openings

## Overview

v0.5 extends the v0.4 `frame_wall` composite operator to support an optional list of door and window openings within a single wall. The wall remains a "regenerated from spec" composite: scalar wall parameters plus an optional openings list together fully specify the wall geometry, and re-running the operator with the same spec produces the same wall.

**Cycle split** (follows the established `UI in vN, bridge parity in vN+1` cadence):
- **v0.5** (this cycle): UI parity — operator extension, properties, UIList, helper functions
- **v0.5.1**: Bridge parity — `frame_wall` MCP tool gains optional `openings` param; smoke test extension

## Architectural Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Openings as operator param vs. mutate existing wall | Operator parameter — extend `frame_wall` | Single source of truth, deterministic regeneration, matches v0.4 pattern |
| Header sizing default | Match wall `nominal` | Refuses to encode load-aware guidance; README documents user must upsize per IRC R602.7 and local code |
| Jack count default | Auto-derive via threshold (≥72" → 2, else 1) | IRC R602.7 convention for typical loading |
| Sill height semantic | Wall-relative (z=0 at bottom of bottom plate) | Consistent with all wall z-coords |
| Header build-up | (2) 2x lumber + 1/2" plywood spacer block | Real residential framing convention; spacer is untagged (scrap from sheathing offcuts) |
| Header Y placement | Flush to y=0 face, 3.5" total stack regardless of wall_nominal | Simple and unambiguous; documented in README; for wider walls the gap is on the +Y face |
| Header Z placement | Header bottom at top of rough opening (= sill_height_in + ro_height_in); cripples fill above to top plates | Standard residential convention — allows arbitrary RO heights, cripples take up slack |
| Bottom plate at doors | Leave continuous | Models framed-but-not-cut state; framers cut after wall is stood up |
| King stud mesh | Share with `wall_stud` (same dimensions) | Linked-mesh efficiency pattern; Object name carries role distinction |
| Validation behavior | Property bounds clamp single values; operator refuses with specific error on cross-field violations | Same layered approach as v0.4 |
| Opening default sizes on Add | Door: 38×82 RO. Window: 36×48 RO with sill 36" | Common residential dimensions |
| New opening x_offset placement | Auto-redistribute all openings evenly via `center_x = wall_length × i / (n+1)` | Sensible default; user edits to override; "Distribute Evenly" button for explicit re-trigger |
| Live preview format (valid) | `Preview: N studs + M openings, P plates × L"` | Concise; details live in the UIList directly |
| Live preview format (invalid) | First-failure message with 1-based opening index | Helps user find the offending row immediately |
| Cripple naming | `header_cripple` (above headers) and `sill_cripple` (below window rough sills) | Carpenter-standard terms |

### `recommend_jack_count(ro_width_in: float) -> int`

```python
def recommend_jack_count(ro_width_in: float) -> int:
    """Jack stud count per side for a rough opening.
    
    Returns 2 for openings >= 72" (6'), else 1. IRC R602.7 convention
    for typical 2x4/2x6 walls with conventional loading. The frame_wall
    operator uses this as the default when a new opening is added; the
    user can override per-opening.
    """
    return 2 if ro_width_in >= 72.0 else 1
```

### `opening_framing_layout(opening, wall_nominal, wall_height_in, top_plate_count, bottom_plate_count) -> dict`

Pure geometry calculation for one opening. Returns a dict with all the x/z coords and lengths needed to place the opening's framing pieces. No `bpy.` calls.

Coordinate stackup (origin at z=0 = bottom of wall):

```
top of wall:                    z = wall_height_in
bottom of top plates:           z = wall_height_in - top_plate_count × 1.5
top of header:                  z = same OR header_bottom_z + header_member_z_height
bottom of header:               z = sill_height_in + ro_height_in
top of rough opening:           z = same as bottom of header
bottom of rough opening:        z = sill_height_in    (= 0 for doors)
top of rough sill (windows):    z = sill_height_in
bottom of rough sill (windows): z = sill_height_in - 1.5
top of bottom plates:           z = bottom_plate_count × 1.5
bottom of wall:                 z = 0
```

Where `header_member_z_height = LUMBER_TYPES[header_nominal][1]` (the wider dimension — 3.5" for 2x4, 5.5" for 2x6, etc.).

The returned dict should include at least:

| Key | Meaning |
|-----|---------|
| `king_left_x`, `king_right_x` | Outer-edge x-coords of the two king studs |
| `jack_left_xs`, `jack_right_xs` | Lists of left-edge x-coords for jack studs |
| `header_x_start`, `header_x_end` | x range of header members (= jack outer edges) |
| `header_z_top`, `header_z_bottom` | z range of header members |
| `header_member_length_in` | Cut length of each header member |
| `spacer_y_start`, `spacer_y_end` | y range of plywood spacer (between the two header members) |
| `rough_sill_x_start`, `rough_sill_x_end` | x range; `None` for doors |
| `rough_sill_z_top`, `rough_sill_z_bottom` | z range; `None` for doors |
| `king_length_in` | Cut length (= wall stud length) |
| `jack_length_in` | Cut length |
| `cripple_top_zone` | `(z_bottom, z_top)` for header cripples; `(None, None)` if too short |
| `cripple_bottom_zone` | `(z_bottom, z_top)` for sill cripples; `(None, None)` for doors or too short |

X-stackup for the opening framing (left to right):

```
king_left_x  →  jack_left_xs[0..jack_count-1]  →  RO (x_offset .. x_offset+ro_width)  →  jack_right_xs[0..jack_count-1]  →  king_right_x
```

Where stud thickness `t = LUMBER_TYPES[wall_nominal][0]` (1.5" for 2x4 walls).

```
king_left_x   = x_offset - jack_count × t - t        (outer edge of left king)
jack_left_xs  = [x_offset - i × t for i in 1..jack_count]  (left edges of jacks, innermost first)
jack_right_xs = [x_offset + ro_width + i × t for i in 0..jack_count-1]
king_right_x  = x_offset + ro_width + jack_count × t + t   (outer edge of right king)
```

Cripple zones:
- `cripple_top_zone`: `(header_z_top, wall_height_in - top_plate_count × 1.5)`. If length ≥ 1.5", populate; else `(None, None)`.
- `cripple_bottom_zone` (windows only): `(bottom_plate_count × 1.5, sill_height_in - 1.5)`. If length ≥ 1.5", populate; else `(None, None)`. Always `(None, None)` for doors.

### `filter_studs_around_openings(stud_positions, nominal_thickness_in, openings, layout_per_opening) -> list[float]`

Given the regular OC stud positions and the per-opening layout, return only those positions that don't collide with any opening's king-bracket range. A stud at x with thickness t is "in" a king-bracket range `[king_left_x, king_right_x]` if `(x + t > king_left_x) AND (x < king_right_x)` — standard interval overlap test.

### `validate_openings(openings, wall_length_in, wall_height_in, wall_nominal, top_plate_count, bottom_plate_count) -> tuple[bool, str]`

Validate the opening list. Returns `(True, "")` on success, or `(False, error_message)` on first failure.

Checks in order, returning first failure with 1-based opening index:

1. **wall_openings_within_wall**: For each opening, `king_left_x >= 0` AND `king_right_x <= wall_length_in`. Error: `"Opening {i+1} extends past wall edge"`.
2. **wall_openings_no_overlap**: For all pairs (i, j) with i < j: opening i's king-bracket must not overlap opening j's king-bracket. Error: `"Opening {j+1} overlaps Opening {i+1}"`.
3. **opening_height_fits**: For each opening, `header_z_top <= wall_height_in - top_plate_count × 1.5`. Error: `"Opening {i+1} too tall to fit under top plates"`.
4. **rough_sill_clears_bottom_plate** (windows only): `sill_height_in - 1.5 >= bottom_plate_count × 1.5`. Error: `"Opening {i+1} rough sill overlaps bottom plate stack"`.

### `redistribute_openings_evenly(openings, wall_length_in)`

```python
def redistribute_openings_evenly(openings, wall_length_in: float) -> None:
    """Reposition all openings to evenly-spaced layout.
    
    Sets opening.x_offset_in = (wall_length × (i+1) / (n+1)) - (ro_width / 2)
    for each opening i in 0..n-1 (where n = number of openings).
    
    Called by add_door, add_window, and distribute_openings operators.
    Mutates the CollectionProperty in place.
    """
    n = len(openings)
    if n == 0:
        return
    for i, opening in enumerate(openings):
        center_x = wall_length_in * (i + 1) / (n + 1)
        opening.x_offset_in = max(0.0, center_x - opening.ro_width_in / 2.0)
```

## Operator Extension: `PRAXOVA_OT_frame_wall`

In `ops_frame.py`, extend `execute()` with the opening flow inserted between existing scalar validation and the existing stud placement step.

New flow:

1. After existing scalar param resolution (length, height, nominal, plate counts), read `sp.wall_openings` into local list.
2. After existing scalar validation, if openings is non-empty: call `templates.validate_openings(...)`. On failure, `self.report({'ERROR'}, msg)` and `return {'CANCELLED'}`.
3. Create wall Empty (unchanged from v0.4).
4. Place top and bottom plates (unchanged — they run full wall length regardless of openings).
5. For each opening (with `op_idx` = 0-based index):
   a. Call `templates.opening_framing_layout(opening, wall_nominal, ...)` to get geometry.
   b. Place king studs (2, left and right). Share mesh with regular `wall_stud_<nominal>_<king_length>`.
   c. Place jack studs (`jack_count` per side, total `2 × jack_count`). Mesh `wall_jack_<nominal>_<jack_length>`.
   d. Place 2 header members. Mesh `wall_header_<nominal>_<header_member_length>`.
   e. Place header spacer (1/2" plywood block between the two members). Object with mesh `wall_header_spacer_<header_member_length>`. **DO NOT** set `is_lumber=True` — spacer is untagged so it doesn't appear in the cut list.
   f. If WINDOW: place rough sill. Mesh `wall_rough_sill_<nominal>_<ro_width>`.
   g. If `cripple_top_zone` has positive length: for each x in `stud_positions(...)` inside the opening's king-bracket inner-edge range (between the two king inner edges), place a header cripple. Mesh `wall_header_cripple_<nominal>_<cripple_length>`.
   h. If WINDOW and `cripple_bottom_zone` has positive length: same logic, sill cripples below the rough sill. Mesh `wall_sill_cripple_<nominal>_<cripple_length>`.
6. Compute regular stud positions via existing `stud_positions(...)`.
7. Call `templates.filter_studs_around_openings(...)` to remove studs inside king-brackets.
8. Place remaining (filtered) regular studs as in v0.4. Mesh `wall_stud_<nominal>_<stud_length>` (same as kings — shared mesh).

All tagged opening pieces get parented under the wall Empty (existing v0.4 pattern). The untagged header spacer gets parented too (so it follows the wall Empty's transform).

## New Operators in `ui.py`

### `PRAXOVA_OT_add_door`

```python
class PRAXOVA_OT_add_door(bpy.types.Operator):
    bl_idname = "praxova.add_door"
    bl_label = "Add Door"
    bl_description = "Append a door opening with standard 38\"×82\" RO defaults"
    
    def execute(self, context):
        sp = context.scene.praxova_framing
        new = sp.wall_openings.add()
        new.opening_type = 'DOOR'
        new.ro_width_in = 38.0
        new.ro_height_in = 82.0
        new.sill_height_in = 0.0
        new.header_nominal = sp.wall_nominal
        new.jack_count = templates.recommend_jack_count(38.0)
        # x_offset set by redistribute below
        templates.redistribute_openings_evenly(sp.wall_openings, sp.wall_length_in)
        sp.wall_openings_active = len(sp.wall_openings) - 1
        return {'FINISHED'}
```

```python
class PRAXOVA_OT_remove_opening(bpy.types.Operator):
    bl_idname = "praxova.remove_opening"
    bl_label = "Remove Opening"
    bl_description = "Remove the active opening from the list"
    
    @classmethod
    def poll(cls, context):
        return len(context.scene.praxova_framing.wall_openings) > 0
    
    def execute(self, context):
        sp = context.scene.praxova_framing
        idx = sp.wall_openings_active
        sp.wall_openings.remove(idx)
        sp.wall_openings_active = max(0, min(idx, len(sp.wall_openings) - 1))
        return {'FINISHED'}
```

## Naming Conventions

### Mesh names

Pattern: `praxova_mesh_wall_<role>_<nominal>_<length_in>`. The `<length_in>` is formatted consistently with v0.4 (e.g., `91.5` not `91.50`).

| Role | Used for | Notes |
|------|----------|-------|
| `stud` | Regular OC studs AND king studs | Same dimensions; shared mesh |
| `plate_top`, `plate_bot` | Top and bottom plates | Unchanged from v0.4 |
| `jack` | Jack studs | Length = `header_z_bottom - bottom_plate_top` |
| `header` | Header members (2x lumber on edge) | z-extent = `LUMBER_TYPES[nominal][1]` (the wider dim) |
| `header_spacer` | 1/2" plywood spacer between header members | Mesh `praxova_mesh_wall_header_spacer_<length_in>` (no nominal — spacer is always 1/2" ply at header z-height); object is **untagged** |
| `rough_sill` | Window rough sill | 1.5" thick (z), wall_thickness wide (y), ro_width long (x) |
| `header_cripple` | Cripples above header | Length varies per opening |
| `sill_cripple` | Cripples below rough sill (windows only) | Length varies per opening |

### Object names

| Object | Name pattern |
|--------|-------------|
| Wall parent | `Wall_NN` (unchanged) |
| Regular stud | `Stud_<idx>` (unchanged) |
| Top/bottom plate | `Plate_Top_<idx>`, `Plate_Bot_<idx>` (unchanged) |
| King stud | `King_Op<MM>_L`, `King_Op<MM>_R` |
| Jack stud | `Jack_Op<MM>_L_<idx>`, `Jack_Op<MM>_R_<idx>` |
| Header member | `Header_Op<MM>_<idx>` |
| Header spacer | `HeaderSpacer_Op<MM>` (untagged) |
| Rough sill (windows) | `Sill_Op<MM>` |
| Header cripple | `HeaderCripple_Op<MM>_<idx>` |
| Sill cripple (windows) | `SillCripple_Op<MM>_<idx>` |

Where `<MM>` is the 0-based opening index, zero-padded to 2 digits. Blender will append `.001` etc. if Objects with these names already exist (e.g., when regenerating a wall without first deleting children).

## Cut List Impact

**No changes to `ops_cutlist.py` needed.** All tagged opening pieces (kings, jacks, headers, rough sills, header cripples, sill cripples) use the existing LUMBER category with the existing `cutlist_label` format. They flow through the v0.4 two-subsection rendering:

- **CUT LIST** shows per-piece detail with `→ cut to N"` annotations for non-stock-length pieces
- **ORDER SUMMARY** aggregates by stock SKU across orientations

Example for a 96" wall with one door (38×82 RO, 2x4 header, 1 jack/side, 2x4 wall):

```
LUMBER — CUT LIST
      2  x  2x4x8 V                              # 2 king studs (length = stud_length_in)
      2  x  2x4x8 V  → cut to 80.5"              # 2 jack studs
      2  x  2x4x8 H  → cut to 41"                # 2 header members
      N  x  2x4x8 V  → cut to 7.5"               # header cripples (count depends on OC pattern)
      M  x  2x4x8 V                              # remaining regular OC studs (filtered)
      3  x  2x4x8 H  → cut to 96"                # plates (top×2 + bottom×1)

LUMBER — ORDER SUMMARY
     (2+2+N+M)  x  2x4x8  (...orientations...)
```

The plywood spacer is untagged → invisible to the cut list. Real builds source it from sheathing scrap, so no order line is appropriate.

## Header Sizing — README Section

Add a new section to `README.md` (between "Metal panels — generic profile" and "Geometry orientation"):

```markdown
## Header sizing

The `frame_wall` operator's per-opening `header_nominal` defaults to the wall's `nominal` size — a 2x4 wall gets a 2x4 header, a 2x6 wall gets a 2x6 header. **This default is geometric, not structural.** Real residential headers are sized by the span and the load above (roof, second floor, snow, etc.), and the same opening can need a much heavier header on a load-bearing wall than on a non-bearing partition.

Use the per-opening `header_nominal` override to upsize for real spans and loads. As a rough starting point (NOT a substitute for code review or an engineer):

| RO width | Typical residential header (load-bearing exterior) |
|----------|-----------------------------------------------------|
| ≤ 4'     | (2) 2x6 |
| 4' – 6'  | (2) 2x8 |
| 6' – 7'  | (2) 2x10 |
| 7' – 9'  | (2) 2x12 |

See IRC R602.7 for the prescriptive header tables, your jurisdiction's adopted code for amendments, and an engineer for anything outside the prescriptive tables. The add-on does not validate header sizing against load — it places exactly what you specify.
```

## Out of Scope (deferred to later cycles)

- Multiple walls (corners, junctions) — single isolated wall remains v0.5 scope
- Corner stud treatments (three-stud corner, California corner) — v0.6 or later
- Headers other than (2) 2x + 1/2" plywood spacer build-up (e.g., (3) 2x for heavy loads, steel headers, LVL beams)
- Header-against-top-plates simplification (no cripples) — v0.5 always uses standard header-at-RO-top
- "Standardize header heights across openings" mode (currently each opening's header bottom is at its own RO top)
- Trimmer/double bottom plate at door swing — v0.5 leaves bottom plate continuous
- Window types beyond a simple rough opening (double-hung vs casement, mulled units, etc.)
- Header span-based recommendation function — header defaults to wall nominal in v0.5
