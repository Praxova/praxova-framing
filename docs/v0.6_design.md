# Praxova Framing v0.6 Design — Multi-Wall Coordination

## Overview

v0.6 introduces multi-wall coordination: walls organized into a Building/Level
hierarchy, joined at L corners, and framed together as a unit with proper top
plate continuity at joints.

**Cycle plan:**
- **v0.6** (this cycle): Building + Level containers, L corner joints only,
  three-stud corner style only, multi-tab N-panel, `frame_building` orchestrator,
  in-place wall re-framing
- **v0.6.1**: Bridge parity for v0.6
- **v0.7**: T joints + in-line splice; California corner + ladder blocking styles
- **v0.7.1**: Bridge parity for v0.7
- **v0.8+**: Multi-story (multiple Levels per Building)

## Architectural Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Container hierarchy | Building → Level → Wall | Matches real architectural composition; "Level" disambiguates from "floor system" (joists/sheathing/covering) we'll add later |
| Wall identity | Object name + `PointerProperty` refs | Blender-native; rename-safe via datablock pointers |
| Joint types in v0.6 | L corner only, three-stud only | T joints, in-line splice, California, and ladder blocking deferred to v0.7 |
| Joint placement | `CollectionProperty` on Level | Joints belong to their containing structure, not to individual walls |
| Top plate continuity | Shorter wall's cap plate extends (default); per-joint override | Craft convention — longer walls are harder to splice, so protect their continuity. IRC R602.3.2 requires lapping but doesn't specify which wall |
| Main vs abutting wall ordering | Explicit (`wall_a` = main, `wall_b` = abutting) | Joint creator declares which is which; UI labels them as such |
| Per-wall params storage | Per-wall PropertyGroup attached to wall Empty | Multi-wall requires each wall to remember its own dimensions; replaces v0.5's scene-level wall scalars |
| In-place re-framing | When active is a wall Empty, regenerate children in place; Empty itself is preserved | `PointerProperty` references from joints survive wall re-framing |
| `frame_building` workflow | Orchestrator iterates walls, each wall framed with joint context | Single source of truth (existing `frame_wall` logic + joint-aware extensions), orchestrator just coordinates |
| UI organization | Multi-tab N-panel (Wall Framing tab + new Building tab) under same "Praxova" category | Existing v0.5 UX unchanged for single-wall users; opt-in Building tab for multi-wall |
| Standalone wall edits within a Building | Wall Framing tab still works on Level-parented walls | Both tabs operate on the same wall data; user picks the right tool per moment |
| Cut list scope | Per-Building | Per-floor / per-wall aggregation deferred |

## Data Model

### `PraxovaWallProps` PropertyGroup (NEW — replaces v0.5 scene-level wall scalars)

Attached as `PointerProperty` to every Object (active only when `is_wall=True`).
Stores per-wall framing parameters that used to live on `PraxovaSceneProps`.

```python
class PraxovaWallProps(bpy.types.PropertyGroup):
    is_wall: BoolProperty(default=False)        # marker — detects wall Empties
    
    # Migrated from PraxovaSceneProps:
    wall_length_in: FloatProperty(...)
    wall_height_in: FloatProperty(...)
    wall_nominal: EnumProperty(...)
    wall_spacing_oc_in: FloatProperty(...)
    wall_top_plate_count: IntProperty(min=1, max=4, default=2)
    wall_bottom_plate_count: IntProperty(min=1, max=4, default=1)
    wall_openings: CollectionProperty(type=PraxovaWallOpening)
    wall_openings_active: IntProperty(default=0)
```

`PraxovaSceneProps` keeps the same fields as "scratch / defaults for new walls."
When a wall Empty is the active object, the Wall Framing tab edits that wall's
`PraxovaWallProps`. When no wall is active, the tab edits the scene scratch
(which will be copied to a new wall on next Frame Wall).

### `PraxovaJoint` PropertyGroup (NEW)

```python
class PraxovaJoint(bpy.types.PropertyGroup):
```

## New Operators

```python
PRAXOVA_OT_add_building       # Create Building Empty + default Level under it
PRAXOVA_OT_add_level          # Add Level under active Building
PRAXOVA_OT_add_joint          # Append new joint to active Level
PRAXOVA_OT_remove_joint       # Remove active joint
PRAXOVA_OT_frame_building     # Orchestrator: frame all walls in active Level
```

`add_building`: creates a new Empty with `PraxovaBuildingProps.is_building=True`.
Auto-creates a default Level (`Level_01`) as a child Empty. Sets
`active_building` and `active_level`.

`add_level`: creates a new Level Empty under the active Building. Auto-assigns
`level_index` to be one higher than the highest existing level in the Building.
v0.6 still only frames one Level at a time, but the data structure supports
multi-story for v0.8+.

`add_joint`: appends a new joint to the active Level's `joints` collection.
Sets `wall_a`, `wall_b` to None initially (user picks in UI). Sets
`joints_active` to the new index.

`remove_joint`: removes the active joint.

`frame_building`: the orchestrator — see below.

## `frame_wall` — Changes

The existing `PRAXOVA_OT_frame_wall` operator is significantly extended:

### Determining what to do

When `frame_wall` is invoked:

1. **Active object is a wall Empty** (`obj.praxova_wall.is_wall == True`):
   - Delete the Empty's existing children
   - Regenerate children using the wall's own `PraxovaWallProps`
   - Empty itself is preserved (so joint `PointerProperty` references survive)

2. **Active object is a Level Empty** (`obj.praxova_level.is_level == True`):
   - Create a new wall Empty as a child of the active Level
   - Initialize the new wall's `PraxovaWallProps` from scene scratch
   - Apply scene scratch values
   - Generate the wall's children under the new Empty

3. **Active object is neither**:
   - Create a new top-level wall Empty (v0.5 behavior, no Level parent)
   - Initialize from scene scratch
   - Generate children

### Joint-aware framing

In any of the three cases above, if the wall is parented under a Level that has
joints referencing this wall, the wall's framing is joint-aware:

- Plate lengths at joint ends are modified (shortened for abutting, extended for
  extending wall on the cap plate)
- Interior filler stud added at joint corner if `corner_style == THREE_STUD`
- v0.5 OC stud placement still happens, but the filler stud is in addition to
  the regular end stud

If the wall is not in a Level, or the Level has no joints touching this wall,
v0.5 behavior is unchanged.

## L Corner Geometry — Detail

For a joint connecting Wall A (main) and Wall B (abutting), each wall's
geometry is modified at its joint end. The other end (free end) is unchanged
from v0.5.

### Setup

For concreteness, consider a joint connecting:
- Wall A's END (x = wall_a.length_in) to Wall B's START (x = 0)
- Wall A oriented along +X in its own frame
- Wall B oriented along +X in its own frame; positioned in world space such
  that B's start lands at A's end

(Other end combinations follow the same logic with appropriate role swaps.)

Each wall carries TWO relevant dimensions from `LUMBER_TYPES[nominal]`. They
look the same number for an idealized 2x stock but differ on actual planed
lumber and must NOT be confused — v0.6.0 shipped with this conflation in the
joint code and was corrected here:

- `wt_A` = Wall A's **wall thickness** = `LUMBER_TYPES[wall_a.nominal][1]`
  (3.5" for 2x4, 5.5" for 2x6, etc.) — the depth from interior face to
  exterior face. This is the dimension a perpendicular wall "takes up" at
  the corner.
- `wt_B` = Wall B's wall thickness = `LUMBER_TYPES[wall_b.nominal][1]`.
- `st_A` = Wall A's **stud thickness** = `LUMBER_TYPES[wall_a.nominal][0]`
  (1.5" for 2x4) — the dimension along the wall's length axis. This is
  the x-extent of an OC stud.
- `st_B` = Wall B's stud thickness = `LUMBER_TYPES[wall_b.nominal][0]`.

The rule of thumb in the joint code: if the value represents "how far the
OTHER wall takes up space at the corner," use wall thickness `[1]`. If it
represents "this stud's own width along the wall length," use stud
thickness `[0]`.

### Wall A (main wall) modifications at the joint end

| Piece | v0.5 default | v0.6 with L joint at END |
|-------|--------------|--------------------------|
| Bottom plate | Full length | **Unchanged** — runs full length INCLUDING the corner area |
| Lower top plate | Full length | **Unchanged** |
| Upper top plate (cap) | Full length | **Conditional**: if A is the extending wall, unchanged. If B is extending, A's cap plate is shortened by `wt_B` at the joint end (i.e., runs from x=0 to x=(length - wt_B)) |
| End stud at joint end | Single stud at x = (length - st_A) | **Unchanged** — A's end stud stays |
| **Interior filler stud (NEW)** | — | If `corner_style == THREE_STUD`, add one stud parallel to A, at left-edge x = (length - wt_B - st_A), standard 1.5"×3.5" cross-section, full wall_stud_length |

The filler stud's right edge lands at (length - wt_B), aligning with Wall B's
interior face in world coordinates. The stud provides drywall backing for
Wall B's inside-corner face.

### Wall B (abutting wall) modifications at the joint end

| Piece | v0.5 default | v0.6 with L joint at START |
|-------|--------------|----------------------------|
| Bottom plate | Full length | **Shortened by `wt_A`** — runs from x = `wt_A` to x = length (length reduced by `wt_A`) |
| Lower top plate | Full length | **Shortened by `wt_A`** — same range as bottom plate |
| Upper top plate (cap) | Full length | **Conditional**: if B is the extending wall, full length from x=0 to x=length (the portion from x=0 to x=`wt_A` lays in world coords on top of A's lower top plate at the corner, creating the lap). If A is extending, B's cap plate is shortened to match the lower top plate range |
| End stud at joint end | Single stud at x=0 | **Repositioned** — now at x = `wt_A` (where B's plates actually start) |

### Extending wall resolution

- `AUTO`: shorter wall extends. If `wall_a.length_in < wall_b.length_in`, A extends.
  If `wall_a.length_in > wall_b.length_in`, B extends. If equal, A extends (tie-break to main).
- `A` / `B`: user override.

Result of resolution affects only the cap plate geometry (modifications above).

### Resulting three-stud count at the corner

| Stud | Source |
|------|--------|
| 1. A's end stud at joint end | A's framing (v0.5 logic — unchanged) |
| 2. A's interior filler stud (NEW) | Joint logic — added for THREE_STUD style |
| 3. B's end stud at joint end | B's framing (v0.5 logic; just repositioned to x = `wt_A`) |

Three studs total at the corner = "three-stud corner."

### Cap plate lap (visualization)

```
Top-down view at corner (B extends; LB < LA):

      Wall B (abutting)
           ↑
        ┌──┴──┐
        │     │
        │     │ ← B's cap plate (extended; full length)
   ┌────│─────│────────────────────────┐
   │    │     │                        │
   │    └─────┘                        │ ← A's plates running
   │                                   │   left-to-right (main)
   │ (interior filler stud here)       │
   │                                   │
   └───────────────────────────────────┘
                Wall A (main)

   At the corner:
   - A's lower top plate runs full length (unchanged)
   - A's cap plate is shortened by wt_B at the joint end
   - B's cap plate runs full length, the portion overlapping A 
     creates a lap of depth wt_A (3.5" for 2x4-on-2x4 corners)
```

## `frame_building` Orchestrator

```python
def execute(self, context):
    sp = context.scene.praxova_framing
    level = sp.active_level
    
    # 1. Pre-validation
    if not level or not level.praxova_level.is_level:
        self.report({'ERROR'}, "No active Level. Use Building tab to select one.")
        return {'CANCELLED'}
    
    # 2. Collect walls in this Level
    walls = [obj for obj in level.children 
             if hasattr(obj, 'praxova_wall') and obj.praxova_wall.is_wall]
    if not walls:
        self.report({'WARNING'}, "Active Level has no walls.")
        return {'CANCELLED'}
    
    # 3. Validate joints
    valid, msg = templates.validate_joints(level.praxova_level.joints, walls)
    if not valid:
        self.report({'ERROR'}, msg)
        return {'CANCELLED'}
    
    # 4. Re-frame each wall with joint context
    framed_count = 0
    for wall in walls:
        joint_context = templates.compute_wall_joint_context(
            wall, list(level.praxova_level.joints), 
            building_default_corner_style=sp.active_building.praxova_building.default_corner_style,
        )
        templates.reframe_wall_in_place(wall, joint_context)
        framed_count += 1
    
    # 5. Report
    n_joints = len(level.praxova_level.joints)
    self.report(
        {'INFO'}, 
        f"Framed {framed_count} walls with {n_joints} joints",
    )
    return {'FINISHED'}
```

## New Helpers in `templates.py`

New section "Joint helpers (v0.6)":

### `compute_wall_joint_context(wall_obj, joints, building_default_corner_style) -> dict`

```python
def compute_wall_joint_context(wall_obj, joints, building_default_corner_style):
    """For each end of the wall, find the joint touching it (if any).
    
    Returns:
        {
            'START': JointContextEntry or None,
            'END': JointContextEntry or None,
        }
    
    JointContextEntry is a dict with:
        joint_type: 'L_CORNER'
        role: 'MAIN' | 'ABUTTING'
        paired_wall: Object (the other wall in the joint)
        paired_wall_end: 'START' | 'END' (which end of the paired wall)
        corner_style: 'THREE_STUD' (resolved from AUTO if needed)
        is_extending: bool (True if this wall's cap plate extends at this end)
    """
```

### `resolve_extending_wall(joint, wall_a_length, wall_b_length) -> 'A' | 'B'`

Pure function. Resolves `joint.extending_wall == 'AUTO'` per the shorter-wall
rule. Returns 'A' or 'B'.

### `resolve_corner_style(joint, building_default) -> str`

Resolves `joint.corner_style == 'AUTO'` to the building's default. For v0.6
always returns `'THREE_STUD'`.

### `l_corner_geometry(wall_a, wall_b, joint, joint_context_for_a) -> dict`

Pure function (no `bpy.` calls). Returns a dict with all the geometry pieces
for an L corner viewed from Wall A's perspective:

```python
{
    'wall_a_cap_plate_shortened_by': float,  # 0 or wt_B
    'filler_stud_x': float,                   # x-coord (left-edge) of interior filler stud, or None
    'filler_stud_length': float,              # cut length
    'a_end_stud_x': float,                    # unchanged from v0.5
    # ... other computed values
}
```

A parallel function returns geometry for Wall B's perspective (cap plate
modifications, end stud repositioning, plate length adjustments).

### `validate_joints(joints, walls_in_level) -> (bool, str)`

Validates the joints list. Returns `(True, "")` on success or `(False,
error_message)` with 1-based joint index on first failure.

Checks (in order):
1. Each joint's `wall_a` and `wall_b` are both set and not None
2. Both walls are in `walls_in_level`
3. `wall_a != wall_b` (no self-joint)
4. No two joints reference the same (wall, end) combination
5. (Optional, defer if complex) Walls' actual world-space positions are
   consistent with the joint — endpoints coincide within tolerance.
   For v0.6, omit this check; user is responsible for wall positioning.

### `reframe_wall_in_place(wall_obj, joint_context=None)`

Mutates the scene. Deletes `wall_obj`'s children, regenerates using the wall's
own props plus the joint context.

If `joint_context` is None, regenerates per the wall's `PraxovaWallProps` only
(equivalent to v0.5 behavior with that wall's params).

If `joint_context` is provided, applies per-end modifications to plate lengths,
end stud positions, and adds joint-specific pieces (interior filler studs).

## Validation Rules

For `frame_building`:

1. Active Level set and `is_level == True`
2. At least one wall in the Level
3. For each joint (in order, returning first failure with 1-based index):
   a. `wall_a` and `wall_b` both set
   b. Both walls in this Level's children
   c. `wall_a != wall_b`
   d. No joint duplicates the same (wall, end) — i.e., no wall has two joints
      at the same end

Error message format: `"Joint N: <specific message>"`.

For `frame_wall`:
- All v0.5 validation still applies (opening fit, plate fit, etc.)
- When joint context is present, the wall's plate length after modification must
  still be ≥ 2 × stud thickness. If a joint shortens a wall's plates such that
  they're shorter than this, report an error.

## Naming Conventions

### Object names

- Building: `Building_NN` (auto-numbered scene-wide)
- Level: `Level_NN` (auto-numbered within Building)
- Wall: `Wall_NN` (existing v0.5; user can rename)
- Joint: no Object; joints live as CollectionProperty items

### Mesh names

Existing v0.5 conventions unchanged. NEW mesh role:

- `praxova_mesh_wall_corner_filler_<nominal>_<length_in>` — interior filler
  stud for three-stud corner

### Object names for new pieces

- Interior filler stud: `CornerFiller_Joint<NN>` parented under the **main**
  wall's Empty (wall A)

## Workflows

### Single-wall design (v0.5 UX preserved)

1. User opens Wall Framing tab
2. Sets scalar params in the tab (= scene scratch)
3. Clicks Frame Wall — creates top-level wall Empty
4. v0.5 UX preserved

### Multi-wall building design (NEW)

1. User opens Building tab
2. Clicks "Add Building" — creates `Building_01` Empty + default `Level_01`
3. Active Level auto-set to `Level_01`
4. User opens Wall Framing tab, sets params for the first wall, clicks Frame Wall
5. `Wall_01` is created as a child of `Level_01`
6. User positions `Wall_01` in the viewport (G key, R key)
7. Repeat steps 4-6 for additional walls
8. User opens Building tab → Joints section
9. Clicks Add Joint, picks Wall_01 and Wall_02 in the pickers, sets L corner
10. Clicks Frame Building — orchestrator re-frames all walls with joint context

### Editing an existing wall (NEW for v0.6)

1. User selects a wall Empty in the viewport
2. Wall Framing tab now shows that wall's `PraxovaWallProps`
3. User edits any field (length, height, openings, etc.)
4. Clicks Frame Wall
5. Wall children are deleted; Empty preserved; new children generated using
   updated props
6. Any joint `PointerProperty` references to this wall's Empty remain intact
7. If the wall is in a Level with joints, user typically clicks Frame Building
   afterward to re-apply joint geometry. v0.6 does not auto-trigger that.

## Out of Scope (deferred to later cycles)

- T joints, in-line splice (v0.7)
- California corner, ladder blocking corner styles (v0.7)
- Multi-story (multiple Levels per Building in active use) — v0.6 supports the
  data structure but the workflow assumes one Level at a time
- Auto-snapping walls to joint positions in world space (v0.7+ likely)
- Floor system (joists, sheathing, finished flooring) — separate feature later
- Per-floor or per-wall cut list aggregation
- Header sizing recommendations (still deferred from v0.5)
- Adjacent-wall stud alignment ("studs at the same x-coord on both sides of a
  shared interior wall")

## Cycle Structure

Seven commits, in order.

### Commit 1: Refactor — in-place re-framing + per-wall params

Files: `properties.py`, `__init__.py`, `ops_frame.py`, `ui.py`

The biggest refactor of the cycle. Moves wall scalar params from
`PraxovaSceneProps` (where they've lived since v0.4) to a new
`PraxovaWallProps` PropertyGroup attached to each wall Empty. Adds in-place
re-framing.

**Note**: This is a structural change that affects the Wall Framing tab UI but
adds no new visible features. Test thoroughly — every v0.5 use case must still
work after this commit lands.

Steps:
